# 네이버 카페 글 읽기 (목록·본문·댓글)

카페 글을 **읽어야 할 때** 본다. 올리기(게시)는 다루지 않는다. 아래에서 `<카페주소>` 는 `cafe.naver.com/` 뒤의 영문 주소, `<카페번호>` 는 숫자 cafeId, `<게시판번호>` 는 menuId 다.

## 1. 한눈에

| 읽으려는 것 | 로그인 없이 | 방법 |
|---|---|---|
| 게시판 목록(번호·이름) | 됨 | 2-1 |
| 글 목록(제목·조회수·댓글 수·본문 앞 몇 줄·공개 여부) | 됨 | 2-2 |
| **전체 공개 글**의 본문·댓글 | 됨 | 2-3 |
| 멤버 공개 글의 본문·댓글 | 안 됨("로그인하지 않았습니다") | 사람이 카페에서 보고 붙여 넣는다 |

- 네이버 **공식 카페 API 는 글쓰기·가입만** 있고 읽기는 없다. 아래 주소는 카페 화면이 쓰는 주소(비공식)라 언제든 바뀔 수 있다. 안 되면 주소가 바뀐 것부터 의심한다.
- 전체 공개 여부는 글 목록의 `openArticle` 로 안다. `true` 인 글만 본문을 요청한다.
- 위장 도구는 필요 없다. `User-Agent` 만 넣은 일반 요청으로 된다.
- Claude 브라우저 도구(내장·크롬 확장)는 네이버 카페 화면을 못 연다. 화면이 아니라 아래 주소를 `curl`·파이썬으로 부른다.

## 2. 주소

### 2-1. 카페 번호·게시판 목록

```bash
# 카페 주소 → 카페 번호(cafeId)
curl -s -A "Mozilla/5.0" "https://apis.naver.com/cafe-web/cafe2/CafeGateInfo.json?cluburl=<카페주소>"
# 게시판 목록(menuId, menuName). menuType F=묶음 제목, B=게시판, S=구분선
curl -s -A "Mozilla/5.0" "https://apis.naver.com/cafe-web/cafe2/SideMenuList?cafeId=<카페번호>"
```

### 2-2. 글 목록

```bash
curl -s -A "Mozilla/5.0" "https://apis.naver.com/cafe-web/cafe-boardlist-api/v1/cafes/<카페번호>/menus/<게시판번호>/articles?page=1&pageSize=50&sortBy=TIME&viewType=L"
```

- `result.articleList[].item` 에 글이 있다(`type` 이 `ARTICLE` 인 것만).
- 쓸 값: `articleId`, `subject`, `summary`(본문 앞 몇 줄), `writeDateTimestamp`, `readCount`, `commentCount`, `likeCount`, **`openArticle`**(전체 공개), `blindArticle`, `hasImage`·`hasFile`·`hasMovie`·`hasPoll`, `representImage`(썸네일).
- 쪽을 올리다가 새 글이 안 나오면 끝이다. 한 쪽 50건.
- 옛 목록 주소(`cafe2/ArticleListV2dot1.json`)는 값이 비어 오는 것이 있어 쓰지 않는다.

### 2-3. 본문·댓글

```bash
curl -s -A "Mozilla/5.0" "https://apis.naver.com/cafe-web/cafe-articleapi/v2.1/cafes/<카페번호>/articles/<글번호>?useCafeId=true"
```

- 열리면 `result.article`(제목 `subject`, 본문 `contentHtml`, `writeDate`, `readCount`, `commentCount`, `scrapCount`, 글쓴이 `writer`)과 `result.comments.items[]`(내용 `content`, `updateDate`, 글쓴이 본인 `isArticleWriter`, 답글 `isRef`·대상 `refId`, 지워짐 `isDeleted`, 등급 `memberLevel`)가 온다. `result.tags`, `result.attaches` 도 있다.
- 막히면 `result.reason` 에 사유가 온다: "로그인하지 않았습니다"(멤버 공개), "삭제되었거나 존재하지 않는 게시글입니다".
- 주소 끝 `v3`, `cadi/v3` 같은 다른 판은 안 된다(오류 9999·051).

## 3. 절차

1. 게시판 번호를 찾는다(2-1).
2. 글 목록을 받는다(2-2). `openArticle` 을 꼭 저장한다. 안 저장하면 다시 받아야 한다.
3. **전체 공개 글 한 건으로 본문이 열리는지 먼저 본다.** 열리면 나머지를 받는다.
4. 본문·댓글은 묶음 파일로 디스크에 쌓는다(4장). 채팅이나 세션 메시지로 본문을 흘려 보내지 않는다. 받는 쪽 컨텍스트에 전부 쌓인다.
5. 끝나면 건수(목록의 전체 공개 수 = 받은 수 + 건너뛴 수)를 맞춰 본다.

속도는 **글 사이 0.6~1.0초, 목록 쪽 사이 0.5초**. 6,000건이 1시간 45분쯤 걸린다. 연속으로 실패하면 쉬었다가 멈춘다. 더 빠르게 돌리지 않는다.

## 4. 많이 받을 때 (스크립트로)

수십 건을 넘으면 손으로 부르지 말고 수집 스크립트를 쓴다. 프로젝트에 이미 수집 스크립트가 있으면 그것을 쓰고, 없으면 아래 조건으로 만든다.

- 표준 라이브러리만으로 일반 요청을 보낸다. 3장의 속도를 지키고, 연속 5번 실패하면 멈춘다.
- 끊겨도 같은 명령으로 이어 받는다(끝난 글 번호를 파일에 적어 둔다).
- 결과는 글 10건쯤씩 묶음 파일로 쌓고, 끝난 묶음 목록 파일을 따로 둔다. 본 세션은 목록 파일만 보고, 묶음은 하위 에이전트가 읽어 줄인 결과만 남긴다.
- 먼저 목록 2쪽, 본문 20건만 받아 형식을 확인한 뒤 전체를 돌린다.
- 오래 걸리는 수집은 백그라운드로 돌리고 기록을 파일로 남긴다.
- 저장 폴더에는 `.gitignore` 를 두어 원자료가 커밋되지 않게 한다.

## 5. 지킬 것

- **로그인 쿠키를 넣어 멤버 공개 글까지 받지 않는다.** 계정 보호조치가 걸린다.
- **네이버 검색 화면을 자동으로 긁지 않는다.** 검색 결과 링크의 `art=` 값을 모으려고 검색을 반복하는 것도 포함이다(6-2).
- 닉네임·네이버 아이디는 저장하지 않는다(같은 사람인지만 알 수 있는 값으로 바꾼다). 본문의 전화번호·이메일은 가린다.
- 회원이 쓴 문장을 서비스 화면이나 AI 지식 자료에 그대로 옮기지 않는다. 주제·요지만 쓰고 새로 쓴다.
- 운영 중인 카페에는 읽기만 한다. 쓰기 시험은 테스트용 카페에서 한다.
- 세션이 자동 모드면 본문 요청이 안전 검사에 막힐 수 있다. 우회하지 말고 사용자에게 알려 모드를 바꾼 뒤 진행한다.

## 6. 잘못 짚기 쉬운 것

### 6-1. "본문은 로그인이 필요하다"

글 한 건이 막힌 것만 보고 그렇게 단정하기 쉽다. 그 글이 멤버 공개였을 뿐일 수 있다. 전체 공개 글은 로그인 없이 본문과 댓글까지 열린다.
**한 건이 막혔다고 "안 된다"로 단정하지 말고, 목록의 `openArticle` 이 `true` 인 글로 다시 확인한다.**

### 6-2. 네이버 검색으로 들어오면 열리는 글

검색 결과 링크는 `cafe.naver.com/<카페주소>/<글번호>?art=...` 꼴이다. `art` 는 네이버 검색이 발급한 값이다. 전체 공개 글은 `art` 를 붙이든 빼든 똑같이 열리므로 2-3 주소로 충분하고 `art` 를 쓸 일이 없다. 멤버 공개 글이 `art` 로 열리는지는 확인되지 않았다.

### 6-3. 본문을 메시지로 나눠 넘기기

본문을 다른 세션에 메시지로 나눠 보내면 그 세션 컨텍스트에 전부 쌓인다. 파일로 쌓고 목록 파일만 넘긴다(4장).
